# References: Build or Buy and the Rise of Personal Software

1. [Commercial off-the-shelf](https://en.wikipedia.org/wiki/Commercial_off-the-shelf) - Wikipedia - Describes buying ready-made software or hardware instead of building custom solutions, with typical advantages and risks. Supplies the buy side of the classic make-or-buy frame the chapter extends.

2. [Situated software](https://en.wikipedia.org/wiki/Situated_software) - Wikipedia - Describes software made for a specific small group and context, not for scale. Names the category into which personal and disposable tools fall.

3. [End-user development](https://en.wikipedia.org/wiki/End-user_development) - Wikipedia - Covers methods that let non-professional programmers create their own software. Background for the rise of personal software built by the people who use it.

4. The Cathedral and the Bazaar - Eric S. Raymond - O'Reilly - Raymond opened with the claim that every good work of software starts by scratching a developer's own itch. That origin story is the intellectual ancestor of building a personal tool for one need.

5. Software Engineering at Google - Titus Winters, Tom Manshreck, and Hyrum Wright - O'Reilly - The authors define software engineering as programming integrated over time. That framing clarifies why long-lived software costs more than a disposable script and who answers when it breaks.

6. [Hyrum's Law](https://www.hyrumslaw.com/) - Hyrum Wright - States that with enough users, every observable behavior of a system will be depended on by somebody. Explains why long-lived software is costly to change and why a personal tool never faces this burden.

7. [An App Can Be a Home-Cooked Meal](https://www.robinsloan.com/notes/home-cooked-app/) - Robin Sloan - Sloan tells how he built a small app for family use and compares it to cooking at home. A warm, concrete account of the personal-software motive.

8. [Home-Cooked Software and Barefoot Developers](https://maggieappleton.com/home-cooked-software) - Maggie Appleton - Appleton examines how AI lets non-programmers build software for their own communities, and the risks of unmaintained tools. Connects generation tools to the maintenance question.

9. [In Defense of Not-Invented-Here Syndrome](https://www.joelonsoftware.com/2001/10/14/in-defense-of-not-invented-here-syndrome/) - Joel on Software - Spolsky argues that building core functions yourself can beat buying when the dependency is central. Supplies the pro-build argument the chapter weighs against buying.

10. [Vibe coding](https://simonwillison.net/2025/Mar/19/vibe-coding/) - Simon Willison - Separates careless vibe coding from responsible AI-assisted programming where the developer reviews the result. Frames the accountability question when a generated personal tool breaks.
