# References: Maintenance and Open Source Sharing

1. [Open-source software](https://en.wikipedia.org/wiki/Open-source_software) - Wikipedia - Describes software with source code released under licenses permitting use and modification, with history and models. Gives the sharing context for the chapter.

2. [Copyleft](https://en.wikipedia.org/wiki/Copyleft) - Wikipedia - Explains licenses that require derivative works to stay under the same terms. Defines one side of the permissive-versus-copyleft choice. Compare it with permissive licenses before choosing one.

3. [Creative Commons license](https://en.wikipedia.org/wiki/Creative_Commons_license) - Wikipedia - Covers the family of licenses for sharing creative works with defined permissions. Supports the chapter's guidance on licensing text and images alongside code.

4. Producing Open Source Software - Karl Fogel - O'Reilly - Fogel wrote the standard guide to running an open-source project, from first release to handling newcomers, and made it freely available. It shows how to prepare a repository for strangers.

5. Working in Public: The Making and Maintenance of Open Source Software - Nadia Eghbal - Stripe Press - Eghbal's taxonomy of federations, clubs, stadiums, and toys shows how a project's audience drives maintainer workload. It explains the real, ongoing cost of sharing code.

6. [Open Source Guides](https://opensource.guide/) - GitHub - Practical guides for starting, running, and sustaining open-source projects. Helps students prepare a repository and set expectations as maintainers. Read the sections on maintainers first.

7. [Choose a Creative Commons License](https://creativecommons.org/choose/) - Creative Commons - An interactive tool that picks a license based on how you want others to reuse your work. A hands-on step in the chapter's licensing guidance.

8. [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) - Olivier Lacan - Proposes a simple format for recording notable changes in each release. A low-effort habit that reduces maintenance cost for users and maintainers.

9. [Semantic Versioning 2.0.0](https://semver.org/) - Semantic Versioning - Specifies a major, minor, patch numbering scheme that signals the impact of changes. Gives a shared language for releases in a maintained tool.

10. [Licensing a Repository](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository) - GitHub Docs - Explains how to add a license file to a repository and what happens without one. A necessary step before sharing generated code.
