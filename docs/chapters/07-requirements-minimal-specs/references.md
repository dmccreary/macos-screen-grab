# References: Requirements and Minimal Specifications

1. [Requirements analysis](https://en.wikipedia.org/wiki/Requirements_analysis) - Wikipedia - Describes eliciting, analyzing, and documenting what a system must do. Establishes the process the chapter shrinks into a minimal specification.

2. [Non-functional requirement](https://en.wikipedia.org/wiki/Non-functional_requirement) - Wikipedia - Explains qualities such as performance, security, and usability that constrain how a system behaves. Covers the non-functional side of the chapter's requirements split.

3. [Minimum viable product](https://en.wikipedia.org/wiki/Minimum_viable_product) - Wikipedia - Defines the smallest version of a product that delivers value and supports learning. Parallels the chapter's aim of the smallest specification that keeps a tool small.

4. User Stories Applied: For Agile Software Development - Mike Cohn - Addison-Wesley - Cohn popularized the As a, I want, so that story template and the INVEST checklist for good stories. His format turns a user need into a short, testable requirement.

5. Specification by Example - Gojko Adzic - Manning - Adzic advocated using concrete examples as the shared specification and as executable acceptance tests. His approach clarifies how acceptance criteria stay testable instead of vague.

6. [User Stories](https://www.mountaingoatsoftware.com/agile/user-stories) - Mountain Goat Software - Cohn's own introduction to writing stories, with templates and advice on keeping them small. A free primary source for the story format used in this chapter.

7. [Given When Then](https://martinfowler.com/bliki/GivenWhenThen.html) - Martin Fowler - Explains the Given, When, Then structure for describing behavior as an example. A compact model for writing the acceptance criteria this chapter requires.

8. [Painless Functional Specifications, Part 1: Why Bother?](https://www.joelonsoftware.com/2000/10/02/painless-functional-specifications-part-1-why-bother/) - Joel on Software - Spolsky makes the case for a short, readable specification before coding and shows what it saves. Supports the chapter's claim that a minimal spec pays for itself.

9. [YAGNI](https://martinfowler.com/bliki/Yagni.html) - Martin Fowler - Explains the You Aren't Gonna Need It rule against building features before they are needed. Shows how non-goals protect scope in a minimal specification.

10. [User Stories and Story Examples](https://www.atlassian.com/agile/project-management/user-stories) - Atlassian - Shows how teams write, size, and organize user stories with examples. A practical complement for students drafting their first requirement statements.
