# References: Software Testing: Automated and Manual

1. [Software testing](https://en.wikipedia.org/wiki/Software_testing) - Wikipedia - Surveys testing levels, methods, and goals, from unit tests to acceptance tests. Gives the overview that organizes this chapter. Read it before the specific test types.

2. [Unit testing](https://en.wikipedia.org/wiki/Unit_testing) - Wikipedia - Explains testing of individual units in isolation, with benefits and limits. Supports the chapter's account of what unit tests confirm.

3. [Smoke testing (software)](https://en.wikipedia.org/wiki/Smoke_testing_(software)) - Wikipedia - Describes quick, shallow checks that confirm a build basically works. Defines the smoke test the chapter places between integration and acceptance.

4. Test Driven Development: By Example - Kent Beck - Addison-Wesley - Beck popularized the red, green, refactor cycle: write a failing test, make it pass, then clean up. His worked examples show tests as a design tool, not an afterthought.

5. The Art of Software Testing - Glenford J. Myers - Wiley - Myers framed testing as executing a program with the intent of finding errors, and cataloged systematic test-case design. That mindset separates 'the tests pass' from 'it works'.

6. [The Practical Test Pyramid](https://martinfowler.com/articles/practical-test-pyramid.html) - Martin Fowler (Ham Vocke) - Shows how to balance many fast unit tests, fewer integration tests, and very few end-to-end tests. Explains why the chapter's test layers differ in cost and confidence.

7. [Test Sizes](https://testing.googleblog.com/2010/12/test-sizes.html) - Google Testing Blog - Classifies tests as small, medium, or large by resources and speed rather than by label. A clear way to reason about what automation can run quickly.

8. [Unit Test](https://martinfowler.com/bliki/UnitTest.html) - Martin Fowler - Explains the two meanings of unit test, solitary and sociable, and why definitions vary. Helps students read claims about test suites carefully.

9. [Test Coverage](https://martinfowler.com/bliki/TestCoverage.html) - Martin Fowler - Argues that coverage numbers reveal untested code but do not prove quality. Reinforces the chapter's caution about behaviors automation cannot reach.

10. [XCTest](https://developer.apple.com/documentation/xctest) - Apple Developer Documentation - Reference for Apple's testing framework for Swift and Objective-C projects. Shows how automated tests are written for a macOS tool.
